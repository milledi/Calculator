# Бекенд для кредитного калькулятора

## Стек и решения (согласовано)
- **Express + node-postgres (pg) + сырой SQL** (одна миграция), без ORM.
- **Админка**: SSR-страница, отдаваемая Express (`/admin`), таблица заявок + смена статуса, закрыта basic-auth (логин/пароль из `.env`).
- **Docker Compose**: dev-профиль (vite dev server + proxy) и прод-контур (nginx + `vite build`).
- **Postgres не публикует порты наружу** — только внутренняя сеть compose; фронтенд общается с API через vite proxy (dev) / nginx proxy (прод).

## Структура
```
server/
  src/
    index.js            — запуск Express, routes, static admin
    db.js               — пул pg, применение миграции
    migrate.sql         — таблица applications
    routes/applications.js — POST /api/applications (создание), GET (для админки)
    routes/admin.js     — GET /admin (SSR-список), POST /admin/:id/status
    lib/validate.js     — серверная валидация тела заявки (zod на сервере)
  Dockerfile
  package.json          — express, pg, zod, dotenv
nginx/
  default.conf          — отдаёт dist, /api и /admin проксирует в api
docker-compose.yml      — postgres, api, web (dev: vite)
docker-compose.prod.yml — postgres, api, web (nginx + dist)
.dockerignore, .env.example
```

## Схема БД (server/src/migrate.sql)
```sql
CREATE TABLE IF NOT EXISTS applications (
  id            SERIAL PRIMARY KEY,
  loan_type     TEXT NOT NULL,
  amount        NUMERIC(14,2) NOT NULL,
  term_months   INTEGER NOT NULL,
  monthly_income NUMERIC(14,2) NOT NULL,
  full_name     TEXT NOT NULL,
  monthly_payment NUMERIC(14,2) NOT NULL,
  total_repaid  NUMERIC(14,2) NOT NULL,
  total_interest NUMERIC(14,2) NOT NULL,
  status        TEXT NOT NULL DEFAULT 'new',  -- new | in_review | approved | rejected
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## API
- `POST /api/applications` — валидация (те же правила, что в `src/entities/applicant/model/schema.ts`: границы сумм/сроков по продуктам из `src/shared/config/loanProducts.ts` — продублирую константы на сервере), пересчёт аннуитета на сервере (та же формула из `src/entities/loan/model/credit.ts`), запись в БД, возврат созданной заявки с рассчитанными платежами.
- `GET /api/applications` — список (используется админкой, под basic-auth).

## Фронтенд-изменения
- **Новый хук `src/features/loan-application/model/useLoanCalculatorPush.ts`** (по существующей feature-sliced структуре): инкапсулирует `fetch('/api/applications')`, состояние `status: idle | submitting | success | error`, ошибку сервера; возвращает `{ push, status, error, reset }`.
- В `src/widgets/loan-calculator/ui/LoanCalculator.tsx`: заменить `window.alert()` на вызов хука — при `submitting` блокировать кнопку, при `success`/`error` показывать соответствующий UI.
- В `vite.config.ts`: `server.proxy['/api'] = 'http://api:4000'`.
- Формула аннуитета/константы продуктов дублируются на сервере — сервер считает независимо (недоверяем клиенту).

## Админка (SSR)
- `GET /admin` — basic-auth (`ADMIN_USER`/`ADMIN_PASSWORD` из env, `crypto.timingSafeEqual`), HTML-таблица заявок: дата, тип, сумма, срок, платёж, доход, имя, статус (select), фильтр по статусу через query-param. Инлайн-минимальный CSS, без сборки.

## Docker Compose
**docker-compose.yml (dev):**
- `db`: postgres:16-alpine, `expose: 5432` (без `ports:`), volume для данных, healthcheck.
- `api`: build `server/`, зависит от db (healthy), `ports: "4000:4000"`, при старте применяет миграцию.
- `web`: node:22, vite dev server (`npm ci && npm run dev -- --host`), `ports: "5173:5173"`, проксирует `/api` → `http://api:4000`.

**docker-compose.prod.yml:**
- `db` — так же, без внешних портов.
- `api` — так же (без опубликованного порта, доступ только через nginx).
- `web`: multi-stage build (node → build dist → nginx:alpine), отдаёт dist, `/api` и `/admin` проксирует на `api:4000`, порт `8080:80`.

## Проверка
- `docker compose up --build` → открыть `http://localhost:5173`, отправить заявку, увидеть её на `http://localhost:4000/admin` (basic-auth).
- `docker compose -f docker-compose.prod.yml up --build` → `http://localhost:8080`.
- Убедиться, что порт 5432 не слушается на хосте (`docker compose ps` — нет published ports у db).
- Существующие jest-тесты фронтенда не ломаются.
